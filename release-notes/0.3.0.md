## New

- **Terminal command blocks.** When your shell marks its commands (OSC 133), each command gets a green or red edge at the left of its prompt row, and its exit code and how long it ran at the right. Turn it off with `command_blocks` under `[terminal]`.
- A failed command's prompt row has a Send to an agent control, and the palette has Terminal: Send Command to Agent. It starts a chat with the command, its output and its exit code.
- The terminal suggests the rest of the newest command you ran, in any terminal, that starts with what you've typed, as faint text after the cursor. Press Right or End at the end of the line to accept it. Suggestions are kept in memory only. Turn them off with `history_suggestions` under `[terminal]`.
- Closing-brace hints: the last row of a long block shows its keyword and name faintly after it, like `} fn render`, in every language. Turn it off with `closing_brace_hints` under `[editor]`, and set the shortest block that gets one with `closing_brace_hints_min_rows` (25 by default).
- Pre-commit checks above the commit message in the Changes panel. List project task labels in `pre_commit_checks` under `[git]` (for example `["fmt", "clippy"]`), and they run one at a time as Runs whenever the staged files change and then stay put for 2 seconds, in a trusted folder. Each check shows its state with a Show Run link. A failing check doesn't stop a commit. It's empty by default, so nothing runs unasked.
- **Draft from diff.** The Changes panel has a Draft from diff button, and the palette has Git: Draft Commit Message from Diff. It writes a commit message from the staged changes through the chat's Claude provider. It needs the chat's Claude API key and runs only in a trusted folder.
- Focus mode holds toasts that don't need you in the notifications inbox until you've had no input for 20 seconds. Toggle it from the notifications popup or with Toggle Notification Focus Mode; the bell shows it's on.
- `notifications` under `[workbench]` sets which notifications show as toasts: `"all"` (the default), `"needs_you"` (only those with an action or a question) or `"off"` (all go to the inbox, though an error still shows once). A project file can't set it.
- Debug: Debug Test at Cursor debugs the Cargo or pytest test you're in. The test lens has a Debug item beside Run test, and a failed test's detail has Debug this test.
- **Plugin panels.** Plugins can show panels in the sidebar and bottom docks, built from kiln-ui: text with tones, virtual lists that keep their scroll, events and screen-reader roles. With `panels.realtime`, a panel also gets key events, a tick every `tick_ms`, and a fixed-width cell grid with a tone per cell, enough for small games.
- Plugins can declare settings (`[contributes.settings]`) with user or project scope and secret keys, and read them with `settings.get`. A setting that is wrong in a settings file shows in the Problems panel at its line.
- Plugins can contribute key bindings with `[[contributes.plugin.bindings]]`. A plugin binding never overrides one of the editor's own; when keys clash, the plugin's log says which binding was refused.
- Plugins can run programs in the background with `process.start` (streamed output, backpressure, killing the whole process tree), in a directory the plugin has open. Each program still needs its own `process.spawn:<program>` grant. On Windows the directory is a documented limit. Plugin jobs appear in Runs.
- A plugin's extension can contribute a language server with `[contributes.lsp]` and talk to language servers with `lsp.request` and `lsp.notify`.
- Plugins can keep files of their own, charged against a `background_data` quota (declared with `background_memory` and `background_wall`, with a ceiling under `[extensions]`). Extensions: Clear Plugin Data deletes them, and uninstalling a plugin does too.
- The plugin authoring guide lists all 15 capabilities.

## Improved

- Each item of a code lens is a button for screen readers, named for its title, and clicking it runs its command.

## Fixed

- Extension language servers: the consent you give now covers the whole installed package, not only the scripts it names, and a granted server runs from a snapshot of the package as installed.
- An extension is reloaded, and its consent checked again, when only a package file's execute bits change.
- On Linux, a file created in place of a trashed one can no longer be moved to the Trash by mistake when the file system reuses the old file's identity.
- On Linux, restoring from the Trash no longer writes over a re-created file that reused the trashed file's identity.
- Tool windows moved between the bottom panel and the sidebar open, hide and refresh in the dock they're in, and a tool window that hasn't opened yet is restored to its saved dock.
- On Windows, agent edits are no longer refused as outside the folder when the folder's path is spelled differently from its canonical form.
- Racket highlighting no longer recolours quoted or datum-commented forms as structs.
- Security: updated the WebAssembly runtime, wasmtime, to 48.0.10 for RUSTSEC-2026-0566 to -0573, and url to 2.5.9 for RUSTSEC-2026-0592.
