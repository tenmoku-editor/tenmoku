## Implementation notes

- **Scope.** Respecced (rev 2) to add `crates/fe-workbench/src/plugin_host.rs`: its `PanelEvent` to `WirePanelEvent` conversion is exhaustive, so the new `Key` and `Tick` events can't reach a plugin without it, and only the plugin thread knows when a tick's call has come back. The change there is the two conversion arms (the `dead_code` allows go) and one `plugin_panel::events().delivered(..)` after each tick's call, however it ended. `plugin_panel_grid.rs` is declared from `plugin_panel.rs` (`#[path]`), so `lib.rs` is unchanged.
- **Grid (C1).** `plugin_panel_grid.rs`: one element (a canvas) per row, in the editor theme's font, size and features (`EditorTheme`, from the window's workbench pane, the default dark theme's for a panel drawn alone). Cell: the font's advance of `m` by the editor's line height, `(size * line_height).round()`; the board is `ceil(cols * advance)` by `rows * line` so layout rounding never clips the last column. Review F1: each cell's grapheme is shaped on its own and painted at `col * advance`, clipped to its cell, so nothing moves the next cell. A grapheme the font shapes wider than the advance (CJK, an emoji, or, in the test shaper, e plus a combining accent) is reshaped at `size * advance / width`. A narrower one (a lone combining mark) is centred. One holding a control character (a newline, a tab) is drawn as a space. A reversed cell's ground fills its cell. One `Role::Image` node named by the label; rows and cells have none. Tones: the six tokens `tone_color` uses, on the panel over the window's background; a token under the floor against it is moved the least way toward white or black (`kiln_core::theme::at_least`) to 4.5:1, or 7:1 (`HIGH_CONTRAST_TEXT`) under Increase Contrast. A reversed cell draws the panel's colour on the tone, the same pair. A token that already meets the floor is drawn exactly.
- **Keys (C2).** A `keys = true` panel's root key context is `plugin_panel_keys` plus kiln's new `holds_plain_keys` flag (review F2, respec rev 3: `kiln/crates/kiln-platform/src/keys.rs`, tests in `kiln/crates/kiln-platform/tests/keys_plain.rs`). While the focused element's own context carries it, kiln's shared matcher consults the keymap only for keystrokes with the secondary modifier (gpui's `Modifiers::secondary()`: Cmd on macOS, Ctrl elsewhere) and, while a chord is pending, for its next keystroke; and for Tab with any modifiers (review round 2 F5: `ctrl-tab`, the tab switcher, isn't secondary on macOS; an unbound Tab still reaches the listener, which moves focus). So `secondary-k secondary-t` and `secondary-k z` run as anywhere else, with the usual timeout and replay; a key that fails a chord is matched afresh and then held. Every other keystroke skips the keymap and goes to the element's listener, so no vim, editor or plain workbench binding (F8, F10) takes it. That replaces the round-0 `holds_keys` plus single-key `keys::lookup` fallback, which lost chords. The panel's listener then: Tab moves focus as before; Escape (any modifiers) runs `dock.focus_editor`; a secondary-modifier key is left alone (the keymap had it); anything else goes through fe-plugin's `PanelRuntime::deliver_key` as `PanelEvent::Key`. Keys are read only while the panel's root itself has focus, so a control inside it keeps its own keys. Review F4: Escape that a control in a realtime panel leaves be (an input, a list) also returns focus to the editor, which stops the ticks. The ring is drawn inside the panel's edge (a dock clips outside), in `state.focus_ring`, while the root has focus. Focus on click is GPUI's track-focus mouse-down; on reveal it is the dock's `focus_on_show`.
- **Ticks (C3).** One `Task` per panel with `tick_ms`, at `max(tick_ms, MIN_TICK_INTERVAL)`, started by `on_focus_in` (or at the panel's next render, if focus came before its first draw) and dropped by `on_focus_out` (which GPUI also sends when the window goes inactive), by `set_shown(false)`, and at its next firing once the load is gone, after which it never restarts. Each firing re-checks shown, focused and window-active. Ticks go through the load's `PanelRuntime` (one per plugin load, kept with its event queue, dropped on unload): `deliver_tick` holds `in_call` until plugin_host says the call is back, so ticks never overlap and one falling due meanwhile is dropped, not queued. A tick dropped by the queue's cap releases it too. Review F3: each start or stop of a panel's ticks opens a new tick session (`PanelEvents::open_ticks`, `close_ticks`). A stop takes the panel's tick out of the queue at once. A tick the host has already taken into a batch is checked with `tick_is_current` just before the call, and dropped (releasing the runtime) when its session has ended. Review round 2 F6: sessions belong to a panel instance (`TickSession`, unique in the process), since every workbench window has its own instance of a plugin's panel over one queue and runtime. `close_ticks(plugin, panel, session)` ends only that session and drops only a tick queued in it. The panel ends its session when its timer stops; when its window closes, at once, through an app-level `cx.on_window_closed` for its own window id (review round 2, F6 again: GPUI sends no focus-out as a window goes, and release waits until nothing holds the panel or its workbench); when it is released (`cx.on_release`); and from the timer task itself when `update_in` fails. A tick is an ordinary `on-event` call under `guarded`, so one past the deadline stops the plugin with `Timeout`; `a_running_game_gets_keys_and_is_unloaded_when_a_tick_overruns` checks this end to end with a WebAssembly plugin, and checks a key's WIT lowering too.
- **Mutations checked.** Dropping `holds_keys` fails `keys_reach_a_focused_realtime_panel` (F8 runs the workbench's binding). Dropping the focus-out listener fails `blur_stops_ticks`. Restarting from render after the load went failed `blur_stops_ticks` while the code was being written, and the `load_gone` guard fixed it. Round 2 fixes: without the window-closed hook, `closing_a_window_drops_its_panels_ticks_and_no_one_elses` fails (it holds both panels and a workbench across the closes, so release can't stand in); without the release hook, `closing_a_window_drops_its_panels_ticks_and_no_one_elses` fails; a session-blind `close_ticks` fails `ending_one_instances_tick_session_leaves_a_later_ones_be`; dropping kiln's Tab exception fails `tab_stays_the_apps_with_any_modifier` and `ctrl_tab_switches_tabs_from_a_focused_realtime_panel`. Round 1 fixes: back on `holds_keys`, the panel fails `the_apps_chords_still_run_from_a_focused_realtime_panel`; in kiln, dropping the afresh hold after a failed chord, or holding plain keys while a chord is pending, fails `the_secondary_modifier_and_its_chords_stay_the_apps`; skipping the wide-grapheme fit fails `odd_graphemes_keep_every_cell_in_its_column` and `grid_rows_render_in_the_editor_font`; checking only `in_flight` (not its session) fails `a_tick_waiting_behind_a_busy_plugin_is_dropped_on_blur_and_hide`; Escape at the root only fails `escape_from_a_control_in_a_realtime_panel_returns_to_the_editor`.
- **Known limits.** `panels.reveal` from a plugin is still fe-plugin's `unimplemented`, so "revealed by its command" means the panel's own rail or foot button and the dock commands.
